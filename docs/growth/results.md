## 運用

既存の3時間更新、90分後の補助確認、月曜9:47 JST研究、公開データ保持、HTTP再試行、同一公開concurrency、対象開催回切替を維持。週次で開発用診断も再現し、調整や自動採用には利用しない。

従来は結果照合段階の失敗や、統計条件成立後のPR権限エラーが研究statusへ残らない場合があった。全段階のoutcomeをrun/attempt別の追記履歴とActions成果物に保存する。PR用ブランチへ移動した後でもmainへ戻って履歴だけをpushする。候補コード/提案ファイルをmainへ混入させないことをローカルbareリポジトリで実行検証。

PR作成は既存のGITHUB_TOKEN（contents:write, pull-requests:write）とghを使用。リポジトリの「Allow GitHub Actions to create and approve pull requests」が必要で、利用者から設定保存済みの連絡あり。管理設定のAPI読取権限は接続ツールにない。実データで候補がまだ適格になっていないため、適格研究PRの作成成功は未実証。架空の候補で試験PRを作らない。GitHub cronの時刻保証はなく、通信障害中にGitHub自体へ履歴を保存できない場合もActionsログ/成果物で追跡する。
