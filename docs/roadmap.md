# 次の実装順序

1. **第3段階の評価基盤を第2段階と並行して先に用意する。** 複数シーズンの日程・結果を利用可能な出典から保存し、時間・開催回・チームIDの整合性を検査する。日時単位で過去情報を切り、学習・調整・最終未使用期間を分離する。ホーム固定・リーグ平均・現行式を基準として、的中率、LogLoss、Brier、引き分け適合率/再現率、リーグ別成績を出す。実際の公開予測と結果の照合も追加する。
2. **第2段階：単純な候補から検証する。** Elo、ホーム/アウェイ別Poisson、Dixon–Colesの順で同じ時系列条件で比較する。0を選べる得点分布・引き分けモデルを作る。相手補正・休養日数・昇降格の事前分布を順に追加し、未使用期間で改善しない特徴は採用しない。天気・負傷・出場停止・スタメンは利用条件と過去時点の取得可能性を確認できる場合だけ追加する。
3. **第4段階：購入候補を予算上限で比較する。** シングル/ダブル/トリプルの候補を生成し、13試合カバー確率は試合間独立という仮定を明記する。投票率との差・当選確率・収益を分離し、賞金や控除などが不足する場合は期待収益を表示しない。自動購入は追加しない。
4. **第5段階：スマートフォン画面を改善する。** 開催回・締切・試合確率・根拠・天気の取得状態・予算別候補・公開予測実績をまとめる。検証成績と実運用成績を別表示し、データ不足も明記する。
5. **第6段階：継続評価を自動化する。** 結果照合と精度レポートを更新する。十分な新規データと事前に定めた判定基準で候補を再評価する。複数区間での安定した改善を確認できない場合は現モデルを維持し、比較結果だけを保存する。

各段階を専用PRとテストでレビュー可能にし、mainへのマージ・本番反映・有料サービスはユーザー承認を受ける。精度向上や高額当選を未検証で保証しない。
