## 原因と影響

- [#74](https://github.com/wiepe/judge90-toto/actions/runs/42345474859) と [#75](https://github.com/wiepe/judge90-toto/actions/runs/42375731377) は、どちらも `fetch_toto.mjs` の `Fixture must match exactly once: 1 ＦＣ町田ゼルビア vs ヴィッセル神戸 (0)` で失敗した。
- 販売終了した第1670回から第1672回への切り替えで発生。第1672回のNo.1～4は **リーグカップ戦**。取得元はJ1・J2・J3のリーグ戦（大会725 / 727 / 730）のため、該当する日付の試合がない。チーム名の別名不足・通信障害ではない。

- 両実行ともテスト、過去結果照合、データ保持・コミット、Pagesビルド、配信記録は成功。第1670回の最終正常予測（2026-11-07 11:24:20 JST、締切12:50 JST）は保持されている。実購入の変更・削除とは関係しない。

## 修正内容

1. 過去結果を取得・照合した後、その実行で取得できた新しい日程を使い、対象13試合の対応範囲を確認する。
2. リーグ日程にない試合のみ、公式gameidに対応するページの大会見出し・日付・両チームIDを照合する。リーグカップ戦と明示された試合だけを「未対応」と分類する。単に日程にないだけでは分類しない。
3. 未対応大会を含む場合は、`state: idle` / `reason: unsupported_competition` と対象開催回・締切・未対応試合・理由を保存。新しい予測の生成を止め、正常終了する。これは予測成功ではなく、明示的な対応待ち。
4. 既存予測・購入候補・入力7ファイルを保持する。結果照合・評価・運用履歴の保存は継続し、将来、対応するリーグ戦だけの回になれば既存の更新処理に自動復帰する。
5. 画面に次回の未対応理由を示し、表示中の開催回には「保存予測」と明記。購入画面にも停止理由を表示する。

通信障害、アクセス拒否、未登録クラブ、重複試合、日付・チーム不一致、未確認の大会は引き続きエラーとする。一時的な失敗の再試行やGitHubの通知設定は変更しない。本番モデル、Actionsの実行時刻、mainやPagesの設定も変更しない。
