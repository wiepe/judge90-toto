# 個人購入履歴の保存設計

購入履歴はブラウザーのlocalStorageに暗号文だけを保存する。GitHubリポジトリ、PagesのJSON、Actions、外部サービスへの送信は実装しない。公開されるのは共通UIと暗号化コードだけ。ページを開くだけでは履歴も空の台帳も作成しない。

HTTPS（開発時localhost）とWeb Cryptoが必要。12文字以上の専用パスフレーズをPBKDF2-SHA256/310,000回・ランダム16byte saltでAES-256-GCM鍵へ変換。保存ごとに12byte nonceを再生成し、形式識別子を認証する。鍵は非抽出CryptoKeyとしてセッション内のみ保持し、パスワード入力を消去する。画面切替、タブ非表示、5分無操作または手動でロック。バックアップは同じ暗号形式で端末へ保存。

これは端末内暗号化であり、認証付きサーバーや他ユーザーからの分離を提供するものではない。同一originの悪意あるコードや解除中の侵害端末には耐えられない。公開コードの変更を承認制に保つ。強い専用パスフレーズを使い、共有端末では利用後にロックする。ブラウザーデータ消去時は履歴も失われる。パスフレーズ復旧や自動同期はないため、暗号化バックアップとパスフレーズを別に保管する。

実購入のチェックを明示した場合だけ保存。13桁×実際の口数と100円単価による金額を照合。候補の生成だけでは購入扱いにしない。配当nullは未確定、0は確認した無当選として扱う。回収率・収支は配当を明示入力した確定分に限定し、総購入額と未確定件数も並記する。配当訂正は履歴を追加する。バックアップ取込はIDで冪等、同一IDの競合は既存履歴を上書きせず拒否。保存容量超過も既存履歴を保持し、成功表示しない。

実購入・配当の入力は利用者の記録であり、販売元から検証された購入実績ではない。購入や決済の実行、賞金の推測、自動入力は行わない。

同一端末の複数タブによる上書きを防ぐため、Web Locksで書込みを直列化し、読込時の暗号文と現在値を比較する。変更を検知したら保存を拒否して開き直す。Web Locks非対応ブラウザーでは安全な保存を開始しない。別タブ更新のstorageイベントでもロックする。
