# 第1段階：取得・公開基盤の修復

## 対象と変更

- 対象は13試合の通常toto（商品ID `01`）。mini toto、totoGOAL、BIG、海外・カップ戦は推測で補完しない。
- 公式購入ページの表示開催回、隠しフィールドの商品ID・対象数、販売期間を突き合わせる。購入・投票・フォーム送信は行わず公開ページのGETだけを使用する。
- DOMで直接のセルを読み、投票入力の公式インデックスから試合番号を取り出す。入れ子の成績表を試合と混同せず、繰り返し表示は同一内容の場合だけ統合する。
- 1〜13の欠番・余分な番号・矛盾する重複・同じチーム/試合の重複を拒否。公式ゲームIDも保存する。
- 日付を全月・年越しに対応させ、公式Jリーグ日程の年月日とホーム/アウェイを一意照合する。完了済み試合・未知チームは拒否する。
- リーグ固定リストを廃止。`data/teams.json` のチームIDで同一性を管理し、当該シーズンの公式日程からJ1/J2/J3を確定する。

IDはJUDGE90独自の安定IDで、公式JリーグIDではない。初期60クラブのIDは名称から一度生成して固定したもの。昇降格でIDは変更しない。名称変更は既存IDの別名として追加し、新クラブは出典を確認して登録する。所属リーグをマスターへ固定保存しない。

## 失敗を最新予測に見せない仕組み

`npm run update` は一時領域で全取得・成績集計・予測・買い目生成を実行し、整合性検査後に公開用セットを用意する。途中失敗時は前回の予測データを保持し、`data/update_status.json` にエラーを記録する。

公開する全ファイルに同じ `dataset_id` を付与し、予測・買い目・天気・状態ファイルの世代と開催回を画面で照合する。販売期間外、更新から6時間超、未検証の旧形式、世代不一致、更新失敗は過去データまたは確認不可と表示し、購入金額のパネルを非表示にする。開いたままでも1分ごとに期限と鮮度を再判定する。

前回と新規の予測を `data/history/` に内容ハッシュ付きで追加保存する。既存履歴は削除・上書きしない。予測式・購入最適化の数式は第1段階では変更していない。「信頼度」は「判定スコア」に表示名を変え、的中確率ではないことを明記した。

Actionsでは更新を直列化し、成功時は全セット、失敗時は状態ファイルのみを1コミットにする。GitHub Pagesはそのコミット単位で配信する。以前の個別取得ワークフローも同じ更新処理へ集約し、一部データだけを公開する経路を避けた。フィーチャーブランチの手動実行では公開更新ジョブを実行しない。

実行予定は従来の毎週土曜9:17日本時間を維持。GitHub側での開始遅延は解消を保証しない。公式ページの選択回が販売期間外・未対応商品なら停止し、別の開催回を勝手に選ばない。`JUDGE90_ROUND` を指定する場合も返却ページの開催回一致を必須にする。

## 通信・利用条件

- 接続先ごとにrobots.txtを確認する。404以外の確認失敗や明示的禁止では取得しない。
- HTTPリダイレクトは自動追跡せず停止する。別ホストや別経路へ迂回しない。
- 通常は最低250ms、Crawl-delayの指定があればその値以上の間隔を空ける。
- タイムアウト30秒、通信エラー・408・429・5xxは最大3回。指数的待機とRetry-Afterを守る。60秒を超える待機指定なら、その場で早期再試行せず停止する。
- 403などは再試行しない。APIキー・課金サービス・認証済み個人データは使用しない。
- 公開データであっても無条件に利用可能とは扱わない。新しいデータ源は利用規約・ライセンス・用途・取得上限を確認してから追加する。契約や規約の変更時は取得設定と用途を再確認する。

2026年10月24日の確認では、totoのrobots.txtは `/knowledge/` を禁止し、今回読む購入情報パスは禁止対象ではなかった。Jリーグのrobots.txtは404。Open-Meteoのrobots.txtでは `/v1/forecast` が禁止されていたためAPI本体へアクセスせず、天気は13件すべて取得不可として記録した。天気は既存モデルに未反映なので、その他の取得・予測は継続する。画面に未取得の注意を出す。これを天気取得成功と数えない。

## 検証と限界

実行方法：

```sh
npm ci --ignore-scripts
npm test
npm run update
```

`npm run update` はローカルの公開用JSONを変更するため、実通信の動作確認は必ず作業用コピーで行う。

22件の自動テストは固定の公開メタデータ・試合情報を最小化したサンプルと偽の通信応答を使い、外部サイトへ通信しない。トークン・投票率・対戦統計はテストHTMLに含めない。全月/年越し、10件不足、別商品、番号、重複、販売期限、ID/所属照合、再試行、robots、途中失敗時の保持、予測生成から買い目生成、旧画面互換、鮮度・世代不一致を検証する。

2026年10月24日9:11〜9:12および9:15〜9:16日本時間の実通信確認は作業用コピーで実施。第1665回13試合の取得、3リーグの成績集計、H2H、予測13件、買い目生成、整合性検査と履歴追加が完了した。天気は上記の利用制約で0/13件。既存モデルの的中率改善を確認したテストではない。

過去のActionsログで確定しているのは「10件抽出したため13件チェックで失敗した」ことまで。当時のHTMLは残っていないため、ページ切替の時刻や具体的な当時のHTML構造まで原因確定とはしていない。今回、現在の実HTMLと不足・重複などの再現例を使って、誤取得を許さない抽出へ変更した。

既存の保存済みJSONはこのPRで更新しない。マージ後の最初の成功更新までは旧データと表示される。Actions・Pages本番配信の最終確認は承認後のマージ/実行で行う。DOMテストは実機スマートフォンのレイアウト保証ではない。Node 20/24で22件通過、actionlintで全ワークフロー検査通過。
